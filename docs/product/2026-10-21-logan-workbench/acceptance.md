# 验收与开发顺序

日期：2026-10-21。以下是开发交付必须执行的场景，**不是已经通过的测试报告**。当前只具备部分原型与旧服务验证，真实连接验收待实现后执行。

## 1. 验收方式

每个场景保留输入资产/版本、操作时间、对象 ID、服务端状态、界面结果及关键审计。截图只能证明显示，必须同时验证存储或接口结果；返回 200、按钮能点击或 toast 提示都不能独立算通过。

使用独立测试项目、可重复的合成日志及已知 commit 的测试仓库。至少包含 Native、Web、明文、缺字段、坏记录、未知时区、跨请求、错误版本源码、重复/乱序回执。真实 SDK 和真实模型测试使用明确授权的脱敏样本，不能自动发送用户原型中的导入内容。

验收级别：P=原型状态与交互，S=真实服务与数据库，I=真实集成，R=发布条件。每项标明最低级别，P 通过不能替代 S/I/R。

## 2. 全流程基准用例

以“请求返回后页面仍加载”为场景，准备应用日志缺失、网络日志存在、源码候选三个初始条件。

1. 创建工单并绑定应用/设备/构建/时间；导入网络日志，读取原始事件并选为证据。
2. 打开源码，只得到候选。询问原因：回答只能确认已见的网络事实，列出状态日志和构建映射缺口，不能宣布状态变量未复位就是根因。
3. 从当前工单补采。记录渠道受理、未知送达、SDK 响应、文件上传和解析，不补造缺失的送达回执。先模拟/触发部分成功，仅已解析文件可读。
4. 仅重试未满足范围。新请求关联父请求；成功文件及旧证据 ID 不变。新增应用日志出现后，原对话仍显示原证据快照。
5. 用户选入应用日志和可信映射的源码，再追问。新轮次展示证据增量、相同请求范围及对应 commit。若新日志推翻原假设，明确记录反证并调整下一步。
6. 记录假设验证，生成回写草稿并保存“待验证”。刷新后工单、轮次、补采链、证据、引用和验证仍存在。
7. 记录独立修复验证，再经复核关闭。去掉有效修复验证重复请求关闭时，服务端必须拒绝。

完整流程结束需要可追溯的 issue → collection → asset → parseRun → event/source → snapshot → turn → verification → update 链。任何节点缺失时报告具体阻塞，不用手工拼造成功链。

## 3. 场景与需求对应

| 场景 | 需求 | 级别 | 给定 / 操作 | 通过条件与证据 |
| --- | --- | --- | --- | --- |
| AT-01 | LOG-01 | S | Native/Web 有相同数字 taskId，分别打开 | 两份数据不串用，legacyRef 类型保留，旧详情链接仍有效 |
| AT-02 | LOG-02 | S | 分别导入 JSONL、JSON 数组、明文与合法协议样本 | 原资产 hash 可复算，格式识别可解释；协议样本经正确适配器；完成后能读取真实内容 |
| AT-03 | LOG-02 | S | 超限、二进制伪装、ZIP、缺密钥、上传断线 | 明确错误；无半份正式资产；刷新查询批次，成功项不重复导入；无乱码回退 |
| AT-04 | LOG-03 | P/S | 载入及下载 Web 样例，再尝试载入真实项目 | 演示项目可阅读/关联样例源码，真实项目拒绝混入；来源始终可辨 |
| AT-05 | LOG-04 | S | 5 行中 1 行损坏，严格失败后改跳过重解析 | 新 run 有 4 条可读、1 条诊断；旧 run 和引用不变；两轮参数/解析器版本可查 |
| AT-06 | LOG-04 | S | CRC 错误、解密失败、超资源限制，选择跳过策略 | 整体失败，无部分正式事件；不把安全校验当坏行跳过 |
| AT-07 | LOG-04 | S | 解析取消与发布并发，worker 失去租约后继续提交 | 只有一个终态；旧 worker 不发布；无半批事件或重复 ID |
| AT-08 | LOG-04 | S | 原资产过期后重解析；重新上传同名文件 | 原请求返回 SOURCE_EXPIRED；新文件新 assetId，不替换旧历史 |
| AT-09 | LOG-05 | S | 时间过滤、零命中、无时区记录、相邻上下文后返回 | 原筛选位置可恢复；未知时间单列；列表/直方图同范围，顺序稳定 |
| AT-10 | LOG-05 | S | 相同 requestId 出现在不同环境/设备/构建 | 只展示关联候选和差异，不自动合并成同一故障；时间接近不输出因果 |
| AT-11 | LOG-06 | S | 收藏、移出范围、切解析版本、分别导出 raw/events/investigation | 历史引用固定；三种导出各有实际内容、范围及版本；导出遵守权限 |
| AT-12 | COL-01 | I | 设备仅按日混合采集，用户选 10 分钟应用日志 | 展示预计整日范围并确认；不承诺不支持的端侧类型/分钟裁剪；未确认不发送 |
| AT-13 | COL-01 | I | 设备未知、SDK 不支持、Web 无活动页面或文件已清理 | 明确 unknown/unsupported/no_data；不伪造在线、回捞或上传成功 |
| AT-14 | COL-02 | I | 渠道受理但无送达回执，稍后 SDK 响应 | 两种事实分别显示；送达保持 unknown；SDK ACK 后仍无可读日志直到上传解析成功 |
| AT-15 | COL-02 | I | 回执重复、乱序、同 ID 改内容、伪造身份 | 合法事件去重归并，非法拒绝审计；客户端成功声明不能直接创建 stored 资产 |
| AT-16 | COL-03 | I | 部分成功后重试，及两个工单相似采集 | 新子请求仅重试缺口；旧成功结果不丢；不同工单不能静默合并 |
| AT-17 | COL-03 | I | 取消/超时后迟到 ACK 或文件；旧 ACK 到新 attempt | 原终态不回退，新 attempt 不受旧回执影响；合法迟到文件仅显式关联 |
| AT-18 | COL-04 | S/I | 在已有对话中补采并收到结果提醒 | 返回原工单，新增/重复/缺失可辨；选入后新快照，旧轮次不变；通知已读持久化 |
| AT-19 | SRC-01 | I | 同文件名不同构建；日志自报 commit；映射缺失 | 无可信映射只 candidate/missing；不使用当前 HEAD 冒充现场；引用显示理由 |
| AT-20 | SRC-01 | I | 可信构建映射存在但定位行缺失/仓库无权限 | 分别显示版本匹配位置待定位、unavailable；不编造行号，不泄漏源码 |
| AT-21 | SRC-02 | S/I | 收藏源码、比较修复前后版本、粘贴人工片段 | commit/range/hash 固定，差异两侧身份明确；人工片段 unverified；返回日志定位不丢 |
| AT-22 | INV-01 | S | 创建并编辑工单，关联不同上下文日志，刷新 | 字段及 revision 持久化；不匹配需确认，不改原日志身份；历史可查 |
| AT-23 | INV-02 | S/I | 多轮问题、运行时补证、断线重连、停止、原快照重试 | 问题及父子关系正确；运行输入不变化；查询原轮次，不误判断线；重试有新 ID |
| AT-24 | INV-03 | I | 仅网络日志和候选源码，询问 UI 根因 | 回答标明证据不足；事实有实际片段引用；候选不升级 matched，无依据不下确定结论 |
| AT-25 | INV-03 | I | 补入应用日志和反证后继续问；调换日志顺序 | 明确增量和反证；输出不依赖数组编号；不重复已被推翻的结论而不解释 |
| AT-26 | INV-03 | S/I | 模型返回不存在/未发送引用，输入含恶意指令 | 引用校验拒绝完成或标记不完整；无任意外部访问、自动推送/写工单；检索清单可复核 |
| AT-27 | INV-04 | S | 假设支持、反驳、无法确定及追加修正 | 保存步骤、观察、来源；旧记录不覆盖；支持假设不产生修复已完成状态 |
| AT-28 | INV-04 | S | 用模型建议或勾选核对替代修复验证关闭工单 | 服务端拒绝；有效修复验证含构建、场景、实际结果、执行人、证据才允许复核关闭 |
| AT-29 | INV-05 | S | 从 completed 轮次编辑草稿；双击保存、服务端成功但响应丢失 | 一条更新；刷新可查询真实结果；编辑与原回答区分，所有引用可定位 |
| AT-30 | INV-05 | S | 预览后工单/证据/验证变化；使用 canceled 轮次回写 | 旧草稿被拒绝并保留用户编辑；未完成轮次不能生成有效回写；不覆盖他人修改 |
| AT-31 | SYS-01 | S | 跨项目访问 ID、导出、旧接口、缓存、源码快照 | 所有路径服务端拒绝；旧 API 无旁路；审计无正文泄漏 |
| AT-32 | SYS-01 | S/I | 内容到期、权限撤销、供应商未配置 | 原文及派生摘录不再可读/发送；引用 tombstone；不调用未配置模型或伪造结果 |
| AT-33 | SYS-02 | S/R | 新功能灰度后回滚，旧 Java/Go API、ID 与原型数据对比 | 旧契约不变，无双写；新增数据保留；localStorage 无清理/自动迁移；关闭开关可回旧入口 |
| AT-34 | SYS-02 | S/R | 固定环境执行约定规模；故障恢复与预算超限 | 提供 p95、错误率、队列/内存/资源上限结果；目标不达标不宣称生产可用；就绪门禁独立评审 |
| AT-35 | LOG-04 | S | 空文件、空 JSON 数组、跳过后零有效行 | 不创建可读任务；错误原因明确；沿用原型的空数据保护 |
| AT-36 | INV-02 | S | 两个客户端同时提问；排队时证据过期或权限撤销 | 仅一个活动轮次；第二个问题保留并提示；过期/撤权内容不送模型 |
| AT-37 | INV-05 | S | 首次响应丢失没有 operationId；幂等记录过期后重放 | 按键可查原结果；过期键明确拒绝，不生成重复工单更新 |
| AT-38 | INV-05 | S | 未配置 AI 时保存人工调查；AI 轮次失败后尝试自动转人工模式 | 人工模式作者和证据可追溯，turnId 为空；失败 AI 不能自动伪装成人工已确认结论；关闭条件相同 |

## 4. AI 专项评审

先建立至少 20 个固定调查样本，覆盖网络单证据、候选源码、可信映射、跨请求、缺时区、反证、解析部分成功、补采仍缺失、权限撤销和恶意文本；每类至少 2 例。每例标注可支持事实、不可支持结论、关键反证和下一步所需证据。

由有业务知识的复核者逐项核对，不让模型自己给自己判通过。硬性失败：不存在的引用、跨项目泄漏、候选代码冒充现场、忽略明确反证却仍确认同一根因、把建议当已执行验证、自动关闭工单。样本中这些失败数须为 0；否则修正提示/检索/结构校验并重跑相关集。该小样本只作为试用门槛，不宣称真实问题准确率。

记录模型版本、配置、数据范围、实际输入清单及评审理由，允许“无法确定”作为正确结果。采用新模型或检索策略后重新评审；历史回答不可按新策略自动重写。

| R 发布评审 | 数据/供应商配置确定、迁移演练、回滚、监控、实际规模测试、存储及真实设备联调 | 必需场景无未解决阻塞；readyz 是否放开有独立真实证据 |
