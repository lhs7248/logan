# Web 日志阅读与人工调查优化验收

日期：2026-10-26。范围依据：用户确认上一轮 Web 分析建议，优先修复连续阅读、工单搜索、返回导航和范围一致性，再突出人工调查。沿用现有三项主导航和六个工具，不更换框架、不删除功能或业务数据。

## 产品行为

| 场景 | 最终行为 | 验收结果 |
| --- | --- | --- |
| 加载更多后刷新 | 保留已加载的阅读窗口；稳定批次不因后台状态更新回到前 200 条 | 浏览器加载 400 / 450 条后点击刷新，仍为 400 条 |
| 工单搜索后刷新 | 搜索词和过滤结果都由状态管理，不再只隐藏现有 DOM | 搜索 MiniApp，刷新后仍只有匹配工单 |
| 浏览器返回 | 主动导航记录历史；后台更新不增加历史；恢复项目、工单、批次、工具、尝试和筛选 | 回捞页返回恢复工单搜索；快速连续返回/前进另有回归测试 |
| 页面尝试筛选 | 事件、时间分布和当前尝试导出使用同一 pageAttemptId；另保留导出全部基础筛选结果 | attempt_b 三处均为 190 条，实际下载文件只含 attempt_b |
| 完整尝试状态 | 服务端按完整基础筛选结果汇总，不依赖浏览器已加载多少页 | 第 259、260 条就绪证据在只加载前 200 条时已经计入状态 |
| 结构化日志 | 默认展示页面、事件含义、错误码和报告耗时；点击可读原文及原始字段 | ERROR 行显示 Bundle 加载失败 / REMOTE_LOAD_FAILED，原 JSON 不变 |
| 人工调查 | 默认打开证据；直接记录判断、验证、生成预览和确认回写；保留 AI 与源码入口 | 浏览器完成保存确切日志证据 → 人工判断 → 验证 → 预览 → 回写 |
| 推送及其他能力 | 原有草稿、内部推送请求、签名回调、重试、取消和导入解析保留 | 原推送 HTTP 12 项检查通过；旧 Web 用例全部保留并通过 |

缺失证据仅表述为“当前基础筛选未包含”，不能用 ERROR 筛选后的片段断言整个尝试没有开始或就绪事件。状态仍受基础筛选范围约束，缺少就绪记录也不能确认白屏。阶段导航最多展示每次尝试的前后各 24 条，全量条数和终态由完整结果计算，其他事件仍可分页阅读。

## 实现边界

- 阅读状态、搜索、摘要和路由拆到 [reader-state.mjs](../../../Logan/ServerGo/internal/workbenchui/static/reader-state.mjs)；项目或读取范围变化会丢弃过期响应。
- 页面仍会重验会话和权限；稳定阅读窗口不重复拉取日志和时间分布，工作区无变化时不重建 DOM。并非服务端增量订阅或大容量虚拟列表实现。
- 新增 `GET /parse-runs/{id}/page-attempts`。事件、时间分布和导出共用服务端筛选函数，`pageAttemptId` 进入游标指纹，跨尝试游标被拒绝。没有参数时旧协议保持原行为，不涉及数据迁移。
- 显式历史 URL 的 AI、源码和其他工具选择继续生效；默认工具改为证据。展示时间使用北京时间，原始记录时间保持原值。
- 没有连接真实阿里云、AI 或源码，也不把推送回调表述为客户端送达或日志回捞成功。

## 数据和运行环境

实际浏览器验收仅使用独立 `web-review` 项目的合成数据。重启本轮隔离服务后，状态文件字节及私有配置不变；重新连接仍可读取日志原文、证据、验证和已回写结果。
