# 再次复审：移动端 → Go → Web 调查链

日期：2026-10-22。基线：`1c07503` 后的 SDK 接入工作副本。保留原接口、资料、设计布局、三项导航及六个调查工具；本轮不合并、不推送、不接入阿里云及生产提供方。

## 结论

**本地主链已实际贯通，不能据此宣布真实业务应用、自动精确源码定位和真实 AI 诊断已全部打通。** 上轮验证分开覆盖了移动端发送器和 Go 接收，确有证据空档；本次把实际发送器直接接到 Go，并修正了 7 类问题。此前“全链已通”的理解应限定为上轮记录的本地验收范围。

Android / iOS 主机测试实际运行仓库的上传实现，传输真实 CLogan 公共 API 生成的加密文件，接到同一 Go HTTP 服务并解析。Android 后续调查测试复用该次上传的同一资产，不再另造手动上传作为替代。Android 排程、iOS 文件查找仍为主机替代接缝，不能代替设备 SDK 初始化、落盘、网络权限和真机验收。

## 本轮发现并已修复

| 问题 | 复现及影响 | 修正与验证 |
| --- | --- | --- |
| P1：结构化日志漏脱敏 | 事件 headers 中的 X-Logan-Upload-Token / X-Api-Key 可通过事件、上下文及解密导出出现明文 | 递归识别大小写及分隔符变体；路由回归先失败后通过；设备与上传 ID 保留，授权原文件字节不改 |
| P1：iOS 重定向转发凭据 | 真实 NSURLSession 在两个本地 HTTP 服务之间跟随 302，第二个服务收到合成上传凭据 | 新 headers 上传使用拒绝重定向的专用 session，完成后释放；Android 凭据上传也停止重定向。两端 credential 测试均返回 302，接收端 0 次请求；旧调用仍能按原行为跟随。Android JDK 本次会跟随，但未复现跨端口转发该头，不混称为两端泄漏 |
| P2：补充证据后无法继续调查 | 完成轮次的材料过期后，页面仍强制继承该轮次，服务端拒绝新问题 | 不继承过期、受限、缺失或无可读快照的父轮次；明确提示使用当前证据重新开始。有效多轮和已排除源码的日志轮次继续保留 |
| P2：解析返回抢占新选择 | 新建解析期间切换另一批次，或两份尚未解析文件都没有 runId 时切换，旧请求返回后覆盖当前阅读 | 同时校验提交时 runId / parseAssetId，在响应及刷新后检查；覆盖两个时机及正常选择路径 |
| P2：人工结果未反映到首页 | 保存了人工调查更新，首页仍称“尚未形成判断”，引导使用未配置 AI | 无可用 AI 判断时显示明确标注的已保存人工摘要；新增证据提示摘要待更新；过期 / 受限摘要不展示 |
| P2：Android 未知版本无法上传 | 接收器允许未知版本，示例却强制版本 / 构建非空 | null / 空值省略相应头；已知值保留，禁止换行；实际发送器验证未知头不被编造 |
| P2：iOS 异步头快照是浅拷贝 | 延迟文件查找期间修改传入的 NSMutableString，发送值随之变化 | 每个值拷贝为不可变字符串；延迟回调前修改值并清空原字典的回归先失败后通过 |

## 完整链路的证据强度

| 阶段 | 本次验证方式 | 结论与限制 |
| --- | --- | --- |
| 移动端上传 → Go | `TestNativeSDKWorkbenchHTTPChain` 的 AndroidActualSender / IOSActualUploader 子用例；真实发送实现、CLogan 字节、本地 HTTP、Go Native 解码 | 通过；主机运行，不是真机 |
| 接收身份、回执、解析、原文件 | 上传专用凭据、作用域、字节一致、精确 4 条正文（含 CLogan header）、重试与冲突、解析失败和重解析、恢复 | 通过；设备 / 版本仍是 SDK 声明，不替代设备或 CI 认证 |
| Go → 当前 Web → 工单 → 验证 → 内部回写 | Android 实际发送器向当前服务上传，浏览器选择同一资产、明确关联问题、加入超时事件、保存 uncertain 验证、生成预览并确认回写；再以 API 交叉核对同一对象 ID | 通过，见 live-android-browser-report.json 与截图；原更新保留 |
| 新日志 → 源码候选 → AI 多轮 → 验证 → AI 来源回写 | 新增 `TestNativeSDKSupplementContinuesSourceInvestigationHTTP`：真实 CLogan 与 Git，不可变映射，本地模型 HTTP 协议夹具；新上传不自动入调查，明确补入后第二轮收到新证据，第一轮快照逐字不变，uncertain 验证及回写指向第二轮 | 协议与业务传递通过；源码仍 candidate / verified=false / sdk_reported。模型夹具是确定响应，不是 LLM 排查质量验收 |
| 当前服务未配置模型 | 浏览器实际提问后产生 CONNECTOR_UNCONFIGURED 失败轮次，无虚构回答；新增 SDK 证据确实进入该轮快照 | 正确失败及人工路径通过，不能记为真实 AI 成功 |
| 原资料与新调查恢复 | 最终版本使用同一目录重启，对照资产、解析、证据、问题、验证、轮次、更新、上传回执的全部 ID，再核对更新快照与验证引用 | 通过；未清理旧数据或未提交用户数据 |

## 仍未闭合的真实联调范围

1. **实际业务应用与真机：** Android 测试应用 / iOS 应用尚需配置新接收地址与应用专用上传凭据，在实际设备执行记录、落盘、上传、重试。仓库主机驱动不能证明外部业务应用已集成或已发布。
2. **精确源码定位：** 当前 Native 协议事件提供正文、类型、时间、原始行；没有文件路径 / 源码行号。仅凭构建和选中的文件无法确认具体事故位置。需要应用日志携带明确位置、可信不可变构建映射和仓库配置，才能另验自动精确命中；本轮没有猜测协议或把候选升级为已证实事故源码。
3. **真实 AI：** 当前服务未配置真实模型与项目授权；只验证模型协议、引用、证据传递及未配置降级。供应商连通、真实日志脱敏策略、推理与诊断质量、多轮事实一致性仍未验收。
4. **远程补采：** 阿里云按用户决定继续暂缓；“已上传新日志后继续调查”通过，不等于“下发 push → 真机接收 → 自动上传”的远程回捞闭环通过。
5. **生产提供方和规模：** 生产入口、实际密钥、部署、容量和长时间稳定性不由此次本机验证证明；原兼容服务及旧入口不因本次工作台验收而自动通过。
