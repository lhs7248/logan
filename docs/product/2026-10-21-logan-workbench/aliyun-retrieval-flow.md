# 日志回捞入口：以业务确认的阿里云流程为准

2026-10-21。本说明取代此前以合成设备目录、绑定号及 `retrieve_logs` 示例指令为基础的入口设计。旧演练记录和日志材料保留，不将其视为真实阿里云协议。

## 已确认的业务流程

工单或用户输入提供推送参数 → 调用阿里云推送 → 客户端接收推送消息 → 客户端上传日志 → 平台收到日志并更新状态 → 回捞成功。解析、阅读、关联源码、AI 排查及回写工单在收到日志之后继续。

## 三步入口

1. **填写推送参数**：应用固定为当前已确认的 Android 测试应用，包名 `com.hxl.xlb.test`。选择设备、账号或别名并填写目标值。设备值来自 `NativePushAliyun` Debug 日志的 deviceId；账号是已绑定的业务 userId；别名是已绑定手机号。标签未绑定，禁用。
2. **关联排查信息**：可选用途、工单及故障时段。工单普通设备 ID 不自动转换成阿里云 deviceId；只自动带入明确保存过的阿里云参数，仍需复核。账号和别名绑定由操作人确认，原型不声称已查询云端状态。切换目标类型清空旧目标值和绑定确认，防止误投。
3. **核对并发起**：核对应用、目标类型、目标值、来源和工单。当前按钮为「模拟发起回捞」，只推进本地状态，不实际发送推送。

草稿按全局入口或来源工单分别保存，刷新可恢复。关联工单发起后，将这次明确输入的阿里云目标参数保存在工单中，便于后续补充回捞；不覆盖原工单的设备或版本信息。

## 成功判定与异常

| 阶段 | 判断依据 | 原型显示 |
| --- | --- | --- |
| 阿里云接受 | 推送调用结果 | 等待客户端接收，不认为已回捞 |
| 客户端收到消息 | 客户端接收反馈 | 已收到消息，尚无文件 |
| 客户端上传 | 上传执行状态 | 上传中，不提前成功 |
| 平台接收并更新 | 文件接收并关联到回捞请求 | 回捞成功；等待解析 |
| 解析 | 文件解析结果 | 完成或失败，独立于回捞结果 |

推送失败、接收超时、无日志和上传失败不能产生回捞成功。平台已经收到原文件后，解析失败仍保持回捞成功，可重新解析，不再次推送。失败重试保留原请求和处理记录，使用新的本地关联号。同一目标和范围已有进行中请求时阻止重复发起。

## 尚未确认，不能自行补造的内容

- 阿里云调用的服务端应用配置、消息类型、命令字与消息载荷。
- 客户端执行回捞时如何使用日期、日志类型及上传地址。
- 客户端反馈、文件上传与平台状态通知的具体接口和关联字段。
- 账号或别名实际命中的设备数量及每台设备结果的聚合规则。
- 通知扩展参数：用户说明其用于打开业务页面，需按具体场景确认，不能默认充当回捞命令。

包名不当作阿里云 AppKey。故障时段只作为排查线索，未映射成未知消息协议。账号、别名不当作日志设备身份。新流程合成文件的版本与构建保持未知，不借用工单元数据确认源码。
