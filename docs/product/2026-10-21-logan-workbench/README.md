## 定稿结论

产品主线固定为：**阅读日志 → 建立或进入问题调查 → 添加日志及源码证据 → 提问与追问 → 根据缺口补采 → 将新证据带入下一轮 → 验证假设及修复 → 人工确认并回写工单。**

保留日志阅读、采集任务、问题调查三个一级入口。源码、AI、补证、验证与回写围绕当前调查展开；不再拆成互不关联的功能入口。保留原有列表、上传、Web 样例、解析历史、失败重试、推送追踪、导出及历史数据。

可以据此开始分模块开发、接口模拟和隔离环境联调。上线仍须经过真实 SDK、推送、源码映射、模型和存储验证。代码目前保留的就绪检查限制不能因原型通过而移除。

## 当前技术基线与旧设计的关系

建议在现有 ServerGo / Hertz / GORM / MySQL 中新增工作台模块及独立表，在 LoganSite 中新增工作台页面和适配层。旧 Native/Web 接口及 ID 保持不变。当前原型作为行为参考，模拟回答和模拟事件不进入真实服务。

[2026-10-10 诊断设计](../../superpowers/specs/2026-10-10-logan-diagnosis-design.md)中的独立 Node.js + SQLite 方案不作为本版默认技术路线；自动修复、构建、设备自动验证和发布观察保留为后续路线，本版不承诺实现。此处是依据当前 Go 代码提出的开发建议，不代表已部署或已批准生产切换。

## 需要业务负责人最终拍板的配置

下面给出可用于开发和隔离演练的默认方案；生产值未确认时，对应外部功能保持不可用，不用模拟结果冒充真实结果。无需等待这些配置才能进行内部开发。

| 决策 | 本版建议 | 确认责任 / 时间 |
| --- | --- | --- |
| 首批平台与远程指令渠道 | 页面兼容 Native/Web；先接一款应用、一个渠道；无能力的设备显示“不支持”，Web 无活动页面不保证接收 | 应用、SDK 负责人；真实补采联调前 |
| 工单系统 | 第一版内部问题工单及更新记录；外部工单保持适配入口、默认未配置 | 产品负责人；排期前确定是否必须首期外部写回 |
| 源码身份来源 | CI 构建清单提供应用、平台、构建、包摘要、仓库和 commit 映射；仓库只读 | 应用、CI 负责人；精确源码联调前 |
| 模型和可发送的数据 | 项目级允许名单、脱敏、明确供应商和数据范围；未配置不发送 | 数据及模型负责人；任何真实模型调用前 |
| 数据保留 | 隔离试用建议内容 7 天、无正文审计 180 天；调查保留可申请有期限延长 | 数据负责人；真实数据接入前 |
| 规模及服务目标 | 先验收 10 个并发阅读用户、2 个并发导入任务的试用规模；测量后决定扩容 | 技术及产品负责人；上线评审前 |

各项建议值是可修改的配置基线，不声称用户已经确认。没有选定供应商时不虚构其回执、能力或 SLA。
