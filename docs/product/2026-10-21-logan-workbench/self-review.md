# 开发定稿包自审

日期：2026-10-21。方式：同一助手先核对本地源码及历史验收，再编写规格，再进行一致性与边界复查。没有独立评审者，不把这次自审描述为独立审计。

## 1. 自审结论

四个开发方向已写成需求、数据对象、状态、API 和验收场景；旧能力列入保留矩阵。文档可作为开发讨论及实现基线。真实接口、真实设备/渠道、可信源码映射、模型质量和发布容量尚未验收，不能据此认定产品已经可上线。

## 2. 发现并在规格中解决的问题

| 问题 | 依据/风险 | 已采用的规格修正 |
| --- | --- | --- |
| 旧诊断设计与当前服务架构不一致 | 旧设计以独立 Node/SQLite 为基线，当前已有 Go 服务和兼容路由 | 建议扩展 Go/MySQL，保留旧协议；旧自动修复/发布路线明确放后续，不与本版混在一起 |
| SDK 上报被当成远程推送回捞 | SDK API 提供按日取文件/上报，不证明已有指令接收及 ACK | 增加能力发现、渠道/设备/SDK 独立状态及真实回调要求；不支持时明确阻塞 |
| 分钟和日志种类选择容易过度承诺 | Native/Web 既有上报粒度及类型字段不支持直接推定端侧精准裁剪 | 区分 requested/effective 范围，扩大采集需确认，混合文件解析后筛选 |
| “重新解析”可能误接旧补数工具 | 现有 CLI 为隔离 Native 已完成任务补尾，要求不改变旧 detailId | 新资产、新 ParseRun、不可变证据；旧 CLI 不暴露为通用页面接口 |
| 源文件与已解析内容可能不是同一版本 | Web 源内容更新不必然重建旧详情 | sourceRevision/rawHash/runId 固定，变更提示 source_changed，历史不能被新文件冒名 |
| 只串起按钮，没有可验证的跨对象关系 | 调查需要恢复采集、事件、源码、轮次及回写 | 定义完整 ID 引用链与服务端原子快照；补采由用户选入后续轮次 |
| 候选源码、日志顺序被误当根因 | 原型之前已有相关推理修正，生产模型仍可能重犯 | 可信构建映射、逐引用检查、反证样本和错误类型门槛；候选无法升级 matched |
| 假设验证与修复验证混淆 | 假设支持不证明修复生效 | 两种 purpose、不同结论枚举；关闭工单需修复构建和验证，服务端把关 |
| 重复请求/迟到事件/并发编辑会破坏结果 | 前端按钮禁用无法保证一致性 | 持久幂等、If-Match、事务提交、终态不回退、旧 attempt 不激活新请求 |
| 证据快照与保留期限冲突 | 保留引用副本可能绕过原始内容到期 | 正文及派生摘录统一过期，保留 tombstone/hash；显式有期限保留延长 |
| 原型阈值被当作后端容量 | 浏览器限制与 Go 解码/HTTP 限制不同 | 分开列出现有默认与试用建议；性能目标标为待测，不引用原型测试证明容量 |
| 旧 API 可能绕过新权限 | 仅新页面鉴权不能隔离旧数据入口 | 增加项目归属适配、网关/网络隔离及旁路验收；不能以 UI 隐藏替代 |
| 隔离环境的通过被误当生产就绪 | 现有 readyz 仍返回未完成集成/生产验证 | 保留门禁，真实渠道、云存储、设备及负载单独验收 |

## 3. 第二遍检查与修正

检查对象：状态枚举和合法转换、接口操作是否覆盖页面结果、失败/取消/过期分支、快照引用及权限期限、开发阶段和旧能力是否冲突。

第二遍发现并修正了以下问题：

- 工单转换文字曾把已解决混入“前四种非终态”，改为逐个列出合法转换，重新打开后不能直接跳回已解决。
- 初稿允许空解析任务成功，与原型的空文件/空数组保护不一致，已恢复拒绝并新增 AT-35。
- 上传取消只有交互描述而无接口，已补取消及断线批次查询；明确取消不删除已落地内容。
- 仅凭 operationId 无法处理第一次响应完全丢失，已补按幂等键查询；明确过期键识别规则，防止清理记录后再次执行。
- 未明确同工单同时提问的行为，已补单活动轮次约束、排队期间权限/期限复核及 AT-36。
- 初稿缺少任务等待上限，补上采集、解析、AI 的隔离试用建议超时与渠道 unknown 不盲目重发规则。
- A 阶段承诺人工回写，但初稿接口只接收 AI 完成轮次，已拆清 manual/ai 两种来源并新增 AT-38，保证模型尚未接入时仍可完成调查记录。

本次实际运行结果：

- 原型现有测试重新执行：72 项通过，0 失败、0 跳过。覆盖导入/重解析、状态发布、补采、证据快照、推理边界及回写。运行方式：原型目录 `node --test *.test.js`。
- 文档机器检查覆盖 5 份 Markdown、19 项需求及 38 个验收场景；无未覆盖需求、重复场景编号或失效的本地文件链接。最终计数见 [校验结果](validation.json)。该检查只验证文档引用和覆盖关系，不证明业务规则已实现。
- 嵌套 Logan 业务仓库 `git status --short` 无输出，本次未修改业务仓库。未重新执行浏览器全流程、Go/Java 集成、真实推送/模型或性能验收。

原型目前仍使用有限模拟流程。生产规格中的真实回执、跨工单相似请求提示、服务端权限和并发控制属于实现要求，不能由这 72 项原型测试推定通过。相关差异在验收表标为 S/I/R；本次不改原型已有数据或行为。
