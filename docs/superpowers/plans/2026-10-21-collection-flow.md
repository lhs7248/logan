# Collection flow implementation plan

**Goal:** 落实已确认的采集流程复审，保留旧请求与调查数据。
**Architecture:** 新增纯规则模块与三步发起界面。独立请求保存在 collectionRequests，关联后转入真实工单 requests，ID 和稳定来源键保留；旧记录不迁移。新请求使用目标快照，返回日志身份与工单线索分开。
**Tech Stack:** 原生 JavaScript / CSS、Node test、本地浏览器原型。

## Constraints

- 依据 collection-flow-review.md，用户已授权执行；不重复设计确认。
- 无真实接口；目标目录与返回材料明确标为合成样例。
- 不重置 v2 数据，不改写历史版本，不生成虚假工单承载独立采集。
- 执行在当前会话，不委派。

## Tasks

- [x] 规则：新增 collection-flow-model.js 及测试，验证独立创建、关联、未知身份、换目标、三种时间范围、样例返回构建不继承最近版本。
- [x] 发起：新增 collection-flow.js / CSS；确认目标、故障范围、核对发起三步；草稿恢复；高级参数折叠；工单可选，已解决工单阻止无提示关联。
- [x] 结果：详情先显示目标和下一步，区分预计与观察范围；独立日志可筛选阅读及重解析，再关联或新建工单继续原调查；保留推送/失败/取消/提醒。
- [x] 适配：只对新请求覆盖任务身份与日志内容，保留旧模块与旧测试；新增界面在 index.html 最后加载。
