# 业务测试 App 接入 Logan：实施前核对

## 目标与已有事实

用户要求真实业务测试 App `com.hxl.xlb.test` 采集 → 上传 → Go 严格解析 → 正式 Web 展示，并在 App、服务进程重启后保留配置、原文件和解析结果。阿里云推送、源码映射不在本次范围。

- 实际目标工程为 `hxl-host-app`，不是 Logan 示例工程。其 `android/app/build.gradle` 从环境配置读取 applicationId，测试包源码包含对应回调入口。
- 已连接实体 Android 手机上的目标包为 6.0.1 / 6001，DEBUGGABLE；启动入口为 `com.hxl.app.NativeHomeActivity`，支持 `run-as` 私有文件访问。
- 当前目标原生宿主源码没有发现 Logan 接入；存在青鸟 TTI 适配与其他监控，不能把这些文件直接声明为 Logan 格式。
- Go 原生接收端支持多应用凭据、自动建资产与严格解析；当前本地配置只绑定独立示例包，需要追加业务测试包配置，不能改包名冒充实际接入。
- 业务工程有用户未提交的登录、文档等修改，本次不覆盖、不回退、不提交这些无关改动。

## 方案选择

推荐在真实业务测试包中接入仓库已有 Java/JNI/CLogan，提供 Debug 专用采集状态及手动上传入口。使用真实页面生命周期与允许记录的错误分类形成首批业务日志，验证实际使用过程。

仅把现有青鸟文件导入平台不能证明业务 App 的 Logan 采集上传；改示例包 applicationId 也不能证明业务工程接入，均不作为替代验收方案。

## 允许改动的范围

1. **业务 Android 宿主**：最小初始化接缝、Debug 专用实现与调试入口、Release 空实现；Debug 构建依赖可追溯到本仓库版本的 Logan 原生库。沿用现有签名、包名、权限和业务启动入口。保留已有青鸟、登录、路由及业务数据。
2. **采集内容**：应用启动、页面生命周期、允许名单内的页面/错误分类、版本、平台和随机安装标识。日志不包含账号、手机号、登录 token、完整请求 URL、请求响应正文、聊天或订单等业务内容。既有业务日志和第三方遥测不自动全量转发。
3. **上传与私有配置**：手动上传实际原生加密文件，失败、排队与解析成功分开显示；限制本地 USB loopback 接收地址。上传专用凭据和密钥在 App 私有目录持久化，不进入 APK、Intent、源码、报告或截图。新应用使用独立上传凭据。
4. **Go 运行配置与工具**：追加业务客户端及可重复的配置/验收操作；保留现有管理员凭据、解码密钥、示例客户端、资产和数据目录，不通过删除重建实现接入。
5. **报告**：保存脱敏后的版本、实际资产/任务/回执、内容核对、原文件摘要、重启恢复、失败重试与构建/测试证据。

本次仅实现 Android 测试环境的受控接入；不新增公共 JS API，不宣称 iOS 或业务 Release 完成。依赖采用已有 Logan 代码及许可证，记录源码版本/摘要和构建产物来源，不临时引入其他监控 SDK。回滚为禁用本次 Debug 接入和恢复受影响源码，不卸载或清空业务 App。

## 验收标准

- 新 APK 保持 `com.hxl.xlb.test`，覆盖安装前比较现有证书；签名不兼容时保留原包与数据，不卸载绕过。
- 从真实业务页面操作生成最小化日志，由业务包自身调用实际 Logan 上传接口，不用宿主脚本代传文件替代。
- 平台显示正确业务包、版本、设备身份来源，自动严格解析；逐条对应本次 App 记录，原文件摘要与授权下载一致。
- 重复上传、网络失败和恢复重试不误报、不混淆新旧提交；保留现有示例资产。
- 实际重启服务、关闭重开业务 App 后，私有配置、安装标识、原文件、回执和解析事件保留；再次上传可用。
- 运行受影响 Android 原生构建和测试、Go/运行脚本回归及正式 Web 行为核对。整机重启、云推送、源码映射不计入通过。

## 确认记录

用户已明确确认：“按这个范围直接实施，把真实业务 App 的采集、上传、Go 解析到 Web 展示跑通，再验证重启后配置和日志都保留，已有数据不要动，阿里云推送和源码映射先不处理。”前置核对已完成，实施以该授权和本方案为范围。
