# 兼容与修改边界

- Java 原始行为是兼容参考；有意改变行为必须明确差异、理由和验收标准。
- 不把 501 占位、禁用功能或 readiness 失败采集成兼容成功，不为通过验收放宽预期。
- 不以 Go 输出重写 Java golden。需要更新时先执行原 Java 基线，核对 captures 差异及来源，再在明确任务范围内更新。
- 保持源码指纹检查有效；不能通过删除检查或重写指纹掩盖意外 Java 改动。
- 不重新运行 hz new 覆盖现有工程；生成文件边界以 ServerGo README 为准。
- 数据库迁移、生产写入和部署必须属于用户授权范围；Harness 验证不自动执行这些操作。
- 真实密钥、DSN、用户日志不进入版本化夹具或证据摘要；优先使用合成或脱敏样本。

执行机制：现有 Go contract/golden/source 测试检查其覆盖的兼容行为；其余依靠差异评审。证据：命令退出码、具体用例与 Java/Go 响应差异。失败处理：定位差异并修复或记录经确认的行为变化，禁止自动接受新基线。尚未自动化：完整生产兼容性、秘密扫描、实际操作授权审计。
