# All 20 real HTTP route rehearsal

`script/rehearse-all-interfaces.py` is an explicit opt-in controller for the untouched
original Java WAR on Tomcat 9 and the production Go image, backed by disposable
MySQL 8.4.11. It reuses `DataRehearsal` / `RuntimeVerifier` engine restrictions,
owned-resource cleanup, private files and synthetic database password redaction.
No public port or gateway is opened. Writers run sequentially, with distinct
per-target device namespaces. Go readiness must remain 503.

Required flags are `--docker`, `--host`, `--allow-isolated-runtime`, `--binary`,
`--java-bundle`, `--work-dir`, `--out`, `--http-go-image`, `--namespace-prefix`, and
`--fixture-mode sdk|protocol` (default `sdk`). SDK mode also requires `--sdk-fixtures`. Work must be a fresh shared `/private/tmp` directory, evidence
must be outside the checkout, and all images must already be loaded. The binary
and Java bundle are the same prepared artifacts used by the existing data
rehearsal. The fixtures directory is generated by `tests/sdk` (see its
README) and must contain genuine SDK `native.bin`, encrypted `web-upload.json`,
`manifest.json` with artifact digests, and the matching test RSA private key. The loader requires the expected producer
metadata and exact complete source-path set, rejects traversal/unknown paths, and
checks every source digest against the current unchanged SDK tree before upload.
This checks consistency and freshness; the manifest is not a cryptographic
attestation of how an artifact was produced.

The `sdkFixtureIngestion` / `sdk_fixture_ingestion` flags mean only ingestion
of host-compiled CLogan and Node WebSDK fixtures (emulated IndexedDB and intercepted
XMLHttpRequest). They never certify real browser, native device, or cloud behavior.

The probe uploads SDK bytes, discovers task/detail IDs through HTTP, forces lazy
parsing, and requires every decoded record including SDK marker records. It checks
all manifest routes, successful HTTP and business envelopes, JSON shape/content,
and returned download URLs. A route is removed from positive coverage if its
fixture-specific payload assertions fail, even after HTTP/envelope success.
Each failure records a safe route identifier. Requests use the fixed allowed
localhost origin and compare normalized MIME/JSON UTF-8 charset and fixed CORS
headers (origin, credentials, max-age, vary, methods, allowed headers). JSON
charset spelling/case and comma-list order are normalized. Redirect scheme and
signature query are validated without persisting the Location value; download
content-disposition formatting is outside this all20 comparison scope. Native downloads follow the actual SDK-generated
signed URL and decompress its object bytes; Web downloads validate raw stored log
strings. IDs, write times and UUID-bearing object names are normalized only for
Java/Go comparison. Invalid/error responses cannot count as positive coverage.
A parser failure blocks certification and is recorded per flow; the independent
native/Web flow and the other runtime still run, producing separate failure evidence.

`--legacy-rsa-compat` is an explicit SDK-mode-only diagnostic override. It sets
`GODEBUG=rsa1024min=0` for Go to permit the original published 1023-bit demo RSA
key. Default runs retain the production RSA minimum. Both outer and all20
summaries record whether the override was used; results with it cannot establish
compatibility under the default Go cryptographic policy. Probe/OSS fixture files
are copied into the shared private work directory before container mounting.

Protocol mode uses synthetic single-frame encrypted native bytes and Web v0
vectors solely to check all20 route compatibility. Its summaries explicitly say
`sdkFixtureIngestion: false`; it cannot certify SDK ingestion or cloud behavior. SDK mode
retains strict full-marker assertions and actual encrypted Web v1 input.

Original Java queues Web detail inserts asynchronously and can return an empty
first index after updating task status. The probe polls for at most 15 seconds
until every expected fixture detail ID is published. Empty/partial indexes never
count as positive route coverage. Captures retain the first empty response and
attempt count separately in `observations.webIndexPublication`; Java/Go comparison
uses only successful steady-state responses. Go currently waits for publication.

The local HTTP object fixture stores and returns actual SDK PUT/GET bytes and
supports Java virtual-host and Go path-style addressing. It intentionally does
**not** verify signature cryptography. It prints method/byte-count markers only,
never object names, authorization, or signed query values. Presigned URLs are
validated in memory and excluded from captures. Original application logs are not
persisted by this controller, because they may contain SDK URLs or credentials.

`all20-flow-comparison.json` is emitted before aggregate flow failure is checked.
It compares every shared positive route and gives each native/Web flow its own
status. A flow passes only when both runtimes publish all ten positive routes,
no flow assertion failed, and normalized semantic responses agree. Thus a Web
BMP SDK fixture flow can have partial ingestion evidence while native ingestion
and the aggregate run remain failed. The real browser/device/cloud gates remain
explicitly unexecuted or blocked.

`all20-summary.json` is emitted only after every route and full SDK payload checks
pass for both runtimes and normalized responses agree. The outer `summary.json`
reports failures/blocks and cleanup. A successful local result leaves the real
Aliyun cloud gate blocked. A cloud run must be a separate explicit opt-in using
user-provided endpoint, region, dedicated bucket/prefix and temporary credentials,
including real service-side authentication/signature checks and owned-object
cleanup; this local runner never substitutes fixture success for that evidence.

Run the focused unit checks with:

```
PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest discover -s tests/tools -p test_e2e20.py
```

## 修复后隔离复验

`--historical-objects` 在同一隔离存储对象上创建 Java 基线副本和独立 Go 待解析行，不重置已完成行；前后比较 Java 完整任务/详情行。`historical-object-acceptance.json` 记录恢复内容、行ID及前后快照。

协议模式保持原PKCS样本；下载按各运行时独立CBC字节预期核对，压缩字节差异单独声明，恢复内容必须相同。SDK模式必须Go20全部通过；原Java只允许已定位的首成员保留/目标日志缺失，严格Java捕获仍失败，不算Java20通过。其他差异拒绝。`all20-runtime-acceptance.json` 分开报告各端通过和严格一致状态。
