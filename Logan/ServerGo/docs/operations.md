# 保留期、回收和退出

## 启用顺序

Java 服务、SDK、前端和现有 HTTP 响应保持原样。新增能力默认关闭，不执行自动迁移。先在隔离数据库明确执行 `001_web_processing.sql`、`002_maintenance.sql`，核对表均为 InnoDB，再启用 `LOGAN_MAINTENANCE_ENABLED=true`。它要求已有 Native DB/OSS 配置。所有实例必须指向同一数据库和同一 OSS endpoint/region/bucket/prefix；维护启动会将数据库绑定到该命名空间，已绑定时修改桶或前缀将拒绝启动。历史数据迁入前仍需人工核对其 OSS 归属。Java 的旧清理任务应在切换时停用，避免未经新租约协调的并行删除。

清理启动时立即执行，之后每分钟执行一轮；默认保留七天，按 `add_time < 当前时间 - 保留期` 判断，严格边界与旧服务一致。与 Java 每日定点任务不同，Go 使用有界周期扫描，可通过间隔配置调整。系统时钟应同步；维护租约与重试时间使用数据库 UTC 时间。每轮最多扫描每种任务各 100 条（默认理论上限每类约 14.4 万条/天，实际受执行预算限制，需按上传量调整间隔/批量并观测积压），单事务有五秒预算，每次详情删除最多 500 行；一条任务的详情和任务删除在同一事务提交。超大任务可能因预算回滚，需要监控并人工处理，不能称为无限吞吐的清理。各阶段独立分配执行预算，防止 Native 积压阻塞 Web 清理和对象回收。

## 数据与对象的一致性

维护实例通过共享数据库租约竞争，所有变更校验 owner/fence 和有效期。正在解析且租约有效的任务跳过。过期 Native/Web 任务、详情和处理任务记录一起删除，Native 对象键先登记到持久化回收表。回收前再次检查原始任务引用，仍被引用则保留。

新上传先登记对象，再执行 OSS PUT，最后在同一数据库事务写入任务并将对象标记为 referenced。PUT 失败、任务写入失败或进程退出留下的登记，经过默认 24 小时宽限期后检查引用，确认无引用才回收。上传发布与回收锁定同一对象行，deleting 对象不能再发布任务。宽限期必须大于上传和 OSS 超时之和。

OSS 删除和数据库确认无法组成一个事务：删除成功、确认丢失时，由过期删除租约恢复，再次执行幂等删除。NoSuchKey 视为删除成功，NoSuchBucket/鉴权失败仍视为错误。失败任务持久化重试，最多 12 次后进入 failed，需告警和排查；不会无休止重试。删除后保留只含键哈希的 tombstone，避免键重用。回收表、租约表应随业务数据库备份。

不会扫描桶并删除任意“查不到数据库引用”的对象。启用前已经丢失数据库记录、且没有登记的历史孤儿对象无法证明归属，需独立盘点和审核后采用 OSS 生命周期或受控导入；本实现只自动回收有上传登记或过期任务记录作为归属证据的对象。迁移期间旧 Java 上传没有登记，新清理只能通过过期任务逐步接管。

## 临时文件

开启维护后，Native 上传和解析临时文件进入专属 `logan-servergo/session-*` 目录。目录权限 0700，进程持有文件锁；其他实例只清理超过宽限期且锁已释放的会话。SIGKILL 后锁由操作系统释放，下次扫描可恢复回收。未知目录、符号链接、嵌套目录和特殊文件不删除。进程退出在 HTTP 和解析 worker 结束后才删除自己的会话。旧版散落在系统临时目录中的无归属文件不会自动删除。

## 监控和退出

`LOGAN_METRICS_ENABLED=true` 开启 `/metrics`，由部署网络限制访问。指标包括 HTTP 请求量/延迟/在途数、数据库连接池及等待、Go 堆内存/协程及进程指标、OSS 操作耗时和结果、解析尝试耗时和结果、持久化任务待处理/运行中/失败数、维护操作及 managed-object 待处理/删除中/上传中/失败数量。标签只使用路由模板和有限结果，不包含 URL 参数、用户、日志、对象名或凭据。请求日志同样只记录模板、方法、状态和耗时。pending 包含 retry_wait；OSS get 耗时只统计返回响应头和正文句柄的时间，不包含正文读取。解析 success 表示一次 Process 调用成功返回，不能替代业务完成状态核对。建议告警：持续 failed、pending 长时间不下降、维护错误、HTTP 5xx、DB 等待和 p99 延迟。生产阈值需压测后确定。

SIGTERM/SIGINT 触发停止接收请求并等待已有 HTTP 请求，随后停止领取解析任务、等待当前任务完成。总宽限期由 `LOGAN_EXIT_WAIT` 控制，超过预算取消 worker/请求上下文并关闭连接，最后关闭 OSS、DB 和临时目录。未完成持久化任务由原有租约超时机制恢复。已有空闲 keepalive 连接可能占用宽限期。强制取消后仍须等待处理逻辑响应取消，避免资源提前关闭；平台 terminationGracePeriod 应大于此预算并留出资源关闭时间。

`/livez` 和现有接口契约不变，`/readyz` 仍返回 503，真实依赖和生产验收尚未完成。启用回收会按保留策略使历史日志不再可查询，这是明确的保留期行为。

## 验证边界

SQLmock 覆盖事务回滚、有效解析租约跳过、引用保护、过期删除恢复、确认丢失和 fence 拒绝；替身 OSS 覆盖重试和请求取消；实际子进程覆盖活动文件锁与 SIGKILL 后回收；本机 TCP 覆盖退出行为。它们不能证明真实 MySQL 锁顺序、OSS 网络分区、多实例或真实 SDK 数据的生产可用性。上线前应在隔离真实 MySQL/OSS 上执行中途断连、两实例竞争、删除成功确认失败、SIGKILL 重启和容量压测，核对任务/详情/对象均无误删。
