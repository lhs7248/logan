# Web 日志协议与任务解析

## 范围和启动

本阶段增加全部10个Web映射：上传、search、latest、detailIndex、taskDetail、details、logDetail、exception、getDownLoadUrl和download，路径仍为 `/logan/web/...`，部署上下文默认 `/logan-web`。原Java、SDK、前端与部署配置保持原样。移动端已有3个接口；另7个移动端查询/解析接口尚未迁移，readiness保持503。

默认 `LOGAN_WEB_ENABLED=false`，Web映射仍501。启用前，在隔离数据库人工审查并执行 [001_web_processing.sql](../migrations/001_web_processing.sql)，提供数据库和Web RSA密钥配置。程序检查所需列与四表InnoDB引擎，不自动建表或修改表。迁移仅新增内部任务/上传协调表，不改变原四表、清除历史重复页或新增旧表唯一约束。当前未在真实MySQL执行迁移。

必须沿用与客户端公钥相匹配的私钥，通过 `LOGAN_WEB_RSA_PRIVATE_KEY_FILE` 挂载PEM/DER（PKCS#1或PKCS#8）。不把旧Java中的私钥复制到Go代码、文档或夹具。启动会实际验证当前Go运行时能否使用该密钥。仓库示例旧密钥只有1023位，默认Go拒绝；确需兼容这类历史客户端时，部署显式设置 `GODEBUG=rsa1024min=0`。程序不会自动关闭此检查。不能只替换服务端密钥而保持旧客户端公钥不变。

## 协议与接口兼容

- v0：按逗号拆分、URL表单解码、Commons Codec式宽松Base64、UTF-8文本。保留尾部空片段规则与HTML字符原样写入存储JSON。
- v1：RSA PKCS#1 v1.5展开AES密钥，AES-CTR/NoPadding解密；客户端IV使用原始字节。空字段、未知版本、IV失败按原Java规则处理；非法包不会创建成功任务。
- 明细：解析 `t/c/d`，URL解码内容，数值非法/溢出按Java回退零，按配置时区计算分钟偏移。Java原始合成向量覆盖这部分行为。
- JSON绑定保留Jackson常见标量转字符串、整数字符串、浮点页码截断等规则；空请求与JSON null为HTTP400。未知字段忽略。
- 查询保留毫秒时间、结束时间加一天、页面聚合、每页20个索引、Web索引的 `detailId` 字段、关键词的区分大小写字面包含匹配。按ID查详情保留原OrderUtil中的空位和重复ID规则。
- 下载仍是HTTP201、application/octet-stream与原Content-Disposition格式，按页码拼接已解密日志字符串数组，不增加分隔符。

Search聚合顺序对照JDK/Guava HashMap桶遍历样本，而不是擅自改成日期升降序；latest另按原控制器明确规则排序。极端哈希冲突树化、跨JDK实现及Fastjson非标准JSON语法未穷举；真实SDK标准JSON仍需实采验证。

## 重复页面和持久化任务

重复页仍按日期、设备与页码查找第一条旧任务，仅更新content，不覆盖原元数据、上报时间或状态。**已解析页再次上报后保留原明细和原ID**，下载内容会更新：这是Java既有行为，本阶段不暗中修复。原Java服务执行证据记录了 `exist → updateContent`，没有重置状态。

新增内部状态pending/running/retry_wait/done/failed。首次详情索引请求幂等创建任务并同步等待，后台worker使用服务级context；请求取消不删除已持久化任务。启动及运行中扫描待执行与过期租约，领取CAS增加fence，数据库UTC毫秒时间判定租约；解析期间续租，失去所有权立即取消。失败最多尝试3次，重试间隔1秒；终态失败保留通用错误码，不记录日志正文或密钥。

解析在事务外进行。发布时先锁内部任务、再锁原任务，校验owner/fence/源版本/digest及租约；分批200行插入明细，与原状态和内部done一次提交。失败整体回滚；提交确认丢失后不会盲目删除已提交明细，已完成任务不会因重试重建ID。未解析页覆盖会同时增加revision/fence并重新排队，阻止旧解析结果提交。

首次插入页面的跨实例协调采用日期+页码的较粗锁，覆盖MySQL设备字段大小写、重音和尾空格比较规则；避免不同原始字符串绕开同一业务身份的锁。代价是同日同页码的上传会串行进入短保存事务，尚无吞吐实测。Java不会遵守内部锁/租约，不允许两个版本对同一数据域并发写入和解析。

## 资源和错误边界

输入及解密输出受 `LOGAN_HTTP_MAX_BODY_BYTES` 约束，单次最多100000个协议项/明细。HTTP原始正文最多预读64KiB，再按预算读取。私钥文件读取上限64KiB。worker数及等待者数量有界，查询超时、客户端取消和服务退出均传递context。

任务元数据查询不载入content。下载与详情先查正文长度，再按剩余预算在SQL中复核每行，防止检查后源内容增长绕过限制。索引只投影ID/类型/时间，关键词用二进制INSTR匹配，限制总索引数为max(1,输入字节预算/256)；Search元数据限制为max(1,预算/4096)行，采用行数预算（不是精确内存上限，较大元数据字段会增加内存）。超过预算拒绝整次结果，不返回截断成功数据。上述预算是实验起点，需用历史最大合法数据校准，不是性能验收结果。

内部失败、超时、拥塞和结果超限返回HTTP500空响应；正文超限413。原Java部分服务会吞掉数据库/批写异常，甚至可能返回成功空结果或标记已解析；Go为解析失败保留未完成状态，不伪装成功。这是单列的故障保护差异，需在正式切流前审查。正常接口和已录制参数边界以Java样本验收。

当前解码会在单个受预算约束的页面内保留解析数组（最多100000条），未实现计划中的磁盘逐条暂存。内存会随worker数与页面预算增长；最大历史页事务、数据库锁等待、磁盘/容器配额和实际容量仍需压测后冻结。该阶段不声称整个生产可靠性工作包验收完成。

## 验证与缺口

证据包括原Java协议/明细合成向量、34个含原过滤器的HTTP响应，以及多日期聚合与已解析页覆盖的执行证据。Go逐项比较响应、字段、下载正文、状态与头部；真实TCP测试固定长度/chunked大页面上传、首次解析和连接复用。

SQLmock覆盖CAS失败、续租失败取消、租约接管候选、源变化、过期worker、原子发布回滚、提交确认丢失、批次和各资源边界。内存替身测试并发首次查询、等待者取消后后台继续、失败不发布和明细ID稳定。这些测试不代替真实InnoDB并发、死锁和进程强杀恢复测试。

v1 Java样本的provider配置有明确前提：旧常量是PKCS#1，却交给PKCS8EncodedKeySpec；当前默认SunRsaSign拒绝该组合。测试优先使用BC KeyFactory并保留SunJCE Cipher，执行未修改的原解密代码。不能把这个合成执行样本当成当前默认JVM部署已经兼容的证明。

尚需真实各版本Web SDK日志、隔离MySQL迁移/多实例并发、最大数据事务、前端全流程及容量验证。没有执行生产迁移、部署或切流。
