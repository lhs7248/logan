# Go MySQL 并发锁与 Web 上传修复

本轮仅修改 ServerGo，保留原 Java、SDK、兼容基线及原部署；只在专属隔离容器和合成数据上验证，不操作生产数据、不执行生产切流，也不编译或运行 Java。修复前的一小时失败证据保留，不能用本轮结果覆盖。

## 根因和修复范围

上轮捕获的任务扫描死锁，是耗尽任务的范围 UPDATE 先锁二级索引，而解析发布先锁任务主键再更新相同索引，形成锁顺序冲突。本轮改为有上限的非锁定候选读取，再逐个按任务主键条件更新。条件同时检查 running、owner、fence、候选读取时的 lease_until、当前数据库时间下确已过期以及 attempts 达上限。读取与更新之间发生续租或归属变化时更新为零行，不将新租约错误标记失败。不会扩大批处理上限，也不取消发布端的租约、fence、源版本或摘要检查。

真实 MySQL 并发屏障另复现 Web 上传身份锁与任务 Ensure 的重复键锁升级死锁：旧 INSERT IGNORE 在已存在键上先取共享锁，两个事务随后 SELECT FOR UPDATE 升级互相等待。改为 INSERT ... ON DUPLICATE KEY UPDATE 的原值赋值，在同一身份上直接串行取得排他锁，保留原事务和后续查询。重复键upsert分支不重置任务状态、owner、fence、摘要或时间；原有Ensure同步逻辑保留，已完成任务的同步仍可能更新updated_at。Web 身份仍按原日期/页粗粒度串行，避免把数据库 collation 等价设备拆成不同锁。

这证明了一条可实际导致 Web 上传失败的路径；上轮 10 次失败没有底层错误类别，不能追溯声称每次都来自这条路径。本轮补充有界脱敏 error_class，HTTP 仍返回原 ErrSave/code 格式；压测报告保留数值业务 code，不保存响应正文或原始 SQL。没有增加未知提交结果下的自动事务重放，也没有降低事务隔离级别或新增数据库迁移。

新镜像首轮短档又捕获不同任务间的明细空范围删除死锁：DELETE WHERE task_id 在二级索引末尾保留间隙锁，随后两任务插入互等。补充修复在已持有 job/task 主键锁并完成租约/fence校验之后，非锁定分页读取实际旧明细ID，每批最多500条，再用显式主键索引精确删除；空结果不执行删除。清理、插入及完成状态仍在原事务内，补数和保留期清理继续按原任务锁协调。

## 回归证据

旧源码在隔离 MySQL8.4.11 上实际失败：Web 上传身份锁和 Native/Web Ensure 均出现 1213；旧 Pending 被活动租约行锁阻塞并超时。旧耗尽扫描也不满足批次上限。新实现通过完整 Go/MySQL 集成矩阵，新增用例以真实 performance_schema 等待加屏障控制交错，不依赖碰巧并发：

- 同身份并发上传均成功、任务数精确匹配；重复 Ensure 仍只有一条 job。
- 活动未过期租约被另一连接持锁时，Pending 不被阻塞且 owner/fence 不变。
- 候选读取后分别改变 owner、fence、续租至未来、仍过期但已变化的 lease_until，旧候选均不能终止新状态；Native/Web 分别覆盖。
- 三条已耗尽过期候选、上限两条时，只终止两条，保留归属元数据。
- Native/Web 两个不同空任务同步发布均成功；旧实现两者稳定复现1213。501条历史明细跨批完整替换，替换owner/fence后的旧工作者不能删除历史内容。
- 原有发布回滚/重试、竞争租约、旧 owner 拒绝及强杀解析进程后的 fence 恢复仍通过。

Go full 的 test/race/vet/build 和 126 项工具测试通过。首次完整测试被沙箱禁止监听本机临时测试端口，原失败保留；允许测试端口后完整重跑通过。独立代码评审复核修复与候选读取/更新竞态。控制器另补最终 MySQL 1205/1213 累计计数，避免最后采样间隔或排空期的锁错误漏验；缺少计数同样拒绝，失败时保存完整阶段证据。
