# 移动端协议与 OSS 链路

## 已实现范围

启用移动端配置后，沿用部署上下文（默认 `/logan-web`）：

| 方法 | 路径 | 行为 |
|---|---|---|
| POST | `/logan/upload.json` | 原始二进制帧解密，保存压缩字节到OSS，再写入原native任务表；返回相对下载地址 |
| GET | `/logan/task/:taskId/download.json` | 查原任务表，返回 `/logan/downing?name=...` |
| GET | `/logan/downing?name=...` | 返回302与有效期1小时的OSS签名地址，由客户端直接下载 |

保留Java的HTTP/业务code区分、ERROR_DECRYPT/ERROR_DATABASE/EXCEPTION消息、空400响应及CORS头。任务ID按Java int范围解析。请求头缺失和空字符串分别映射为null和空串，平台非法值、宽松日期、文件名和毫秒时间按原Java样本对照。

OSS对象名为配置前缀直接拼接原格式文件名，后缀仍是`.log`，对象内容是解密后的压缩字节；Content-Type为application/octet-stream，不设置Content-Encoding。签名不额外探测对象是否存在。SDK采用V4签名，签名URL字节与旧SDK不同，以下载语义兼容为目标；真实桶权限及旧前端代理环境仍需联调。

## 协议与资源边界

帧为标识字节1、4字节大端有符号长度、AES-CBC密文；保持Java跳过非标识字节；2026-10-16修复为保留CBC帧明文，在已完成gzip成员边界有界识别PKCS#7/零填充，避免直接删除中间片段真实字节。原Java探测拒绝规则保留。差异及历史对象恢复见 [SDK恢复修复](native-sdk-recovery.md)。

按64KiB分段解密到私有临时文件，不按整文件分配内存。请求总量、单帧、上传并发和整体时间均有预算。异常帧、输入超限及解密失败映射ERROR_DECRYPT。文件在成功、失败和取消后清理；客户端慢传或提前失败时中断剩余正文读取，避免Hertz自动排空长期占用连接。成功请求保持连接复用。

提供受上下文和明文大小约束的gzip解压函数，按Java损坏尾部保留完整行的规则测试；上传路径本身保存压缩内容，不提前解析日志明细。任务解析、明细查询和后台恢复属于后续阶段。

## 写入顺序与故障

先完成OSS PUT，再提交数据库任务；OSS失败不创建任务。数据库失败返回ERROR_DATABASE并保留对象，因为提交响应丢失可能意味着数据库已经成功提交，立即删除会破坏已有记录。错误日志仅记录经过处理的概要。

当前尚未实现持久化孤儿对象对账/回收；需要在后续任务一致性与清理工作包完成。上传不是跨OSS/MySQL的原子事务，禁止把单测替身当成崩溃一致性验收。

## 验证证据

- 独立Java测试工程直接执行未改动的原协议代码，生成12个合成协议向量（含65568字节密文大帧、填充探测、跨缓冲行、CRC损坏和截断）。
- 原Java解析器9个元数据样本；原Controller与原CharacterEncoding/CORS过滤器9个HTTP样本。
- Go对照上述固定证据；GORM使用sqlmock验证事务/回滚/查询；官方OSS SDK实际访问本机HTTP端点验证上传字节、元数据、下载正文、签名有效期、超时、取消和错误脱敏。
- 串联Hertz、协议、服务、官方SDK和GORM替身；真实TCP验证固定长度/chunked大帧、慢上传超时、错误后停止读取、临时文件清理和成功后的连接复用。
- 协议模糊测试检查任意输入的健壮性；测试使用公开合成密钥，不包含生产密钥。

样本不是实际Android/iOS SDK流量。真实SDK各版本、真实MySQL、真实OSS及端到端签名下载尚未验证；没有压测或QPS结论。其余17个接口仍返回501，readiness仍返回503，不具备生产替换条件。
